## 2. 功能模型推断

### 2.1 产品定位（高置信）

一款**每日一句英语听写训练器**：每天生成一道挑战（全局递增编号 #593），播放一句短音频（约 2 秒），用户听写，系统按词判分，给出正确率与正确答案，可付费/限额翻译。辅以"连续天数"打卡和"复习"词表。与项目名 Atomic English 的 SRS 卡片模型天然契合。

### 2.2 三个 tab 的语义（中置信）

- **每日挑战**：当天的主任务入口（截图 B 是它的详情）：编号、日期、连续天数、播放器、听写与判分。
- **连续天数**：打卡日历/ streak 视图（截图未展开，仅 tab 可见）。
- **复习**：错题/生词表（截图 A）：以词为单位列出，点击 ▶ 播放该词发音。7 个词条 `after/again/have/off/started/surfing/years` 正好来自截图 B 的原句 `I have started surfing again after years off.` —— **这是关键证据：复习词条由挑战句中的实词抽取而来**（`I` 被过滤，`started/surfing` 保留原形）。

### 2.3 判分算法（中高置信）

截图 B：`I start`（用户输入） vs `I have started surfing again after years off.`（原句），正确率 `12.50%`。

- 原句按词切分共 8 词：`I / have / started / surfing / again / after / years / off`
- 用户输入 2 词：`I / start`
- 若按"最长公共子序列命中词数 / 原句词数"：`I` 命中 1 词，`start` 与 `started` 不等（精确匹配算错）→ 1/8 = **12.50%** ✅ 完全吻合。

**结论：正确率 = 精确匹配的词数 ÷ 原句总词数；`start ≠ started`，故只有 `I` 命中。** 这是从两个可见数值反推出来的、可验证的算法（1/8=0.125），置信度高。复刻时按此实现，并把"形态变化算错"作为产品行为保留（不做词干归一）。

### 2.4 计数与进度（中置信）

- `#593`：全局挑战序号，按天数递增（每天一题）。
- `连续天数 1`：用户连续完成挑战的天数；截图 B 当天为第 1 天。
- `13%`：截图 A 的周完成率。该周 7 天，13% 约等于 1/7（14.3%）或按"已完成挑战数 / 计划数"计。与"连续天数 1"一致——本周只完成了 1 天。
- 耳机 `4`：与"播放次数 4"数值相同，推测是**当日累计播放次数**或**待复习条目数**；因截图 B 播放次数恰为 4，更可能是前者（跨页共享的"今日已听次数"）。实现为当日累计播放次数，标注为中等置信。
- `普通`：句子难度等级（还有"困难/简单"等），影响 SRS 权重。

### 2.5 翻译配额（高置信）

`还剩 6 次免费翻译`：免费额度按某种周期重置（每日/总量未知）。复刻取"每日 6 次免费"，额度用尽后引导升级——这是可配置常量，不写死业务假设。

## 3. 数据模型（供 packages/domain 落地）

```
Language      = 'en-US' | ...            // 课程语言
Difficulty    = 'easy' | 'normal' | 'hard'
Challenge {
  id: number                              // #593
  date: string                            // 2026-11-19
  sentence: string                        // 正确原句
  translation: string                     // 中文译文
  audioDurationMs: number                 // 2000
  difficulty: Difficulty                  // normal
}
Attempt {
  challengeId: number
  transcript: string                      // "I start"
  playCount: number                       // 4
  accuracy: number                        // 0.125
  createdAt: string
}
Progress {
  streak: number                          // 1
  weeklyCompletion: number                // 0.13
  todayPlayCount: number                  // 4
  freeTranslationsLeft: number            // 6
}
ReviewItem {
  word: string                            // after / again / ...
  sourceChallengeId: number
  nextReviewAt: string                    // SRS 排期
}
```

**词条抽取规则**（由 §2.2 的证据反推）：对 `sentence` 做小写化、去标点、过滤停用词（`I` 这类代词被过滤），保留剩余实词，去重后生成 `ReviewItem`。

## 4. 复刻范围（本次实现）

第一版用 `framework-selection.md` 的技术栈，做**可运行的纯前端闭环**：

- `packages/domain`：判分算法、词条抽取、进度计算（纯 TS，零依赖，可单测）
- `packages/db`：IndexedDB（Dexie）持久化 progress / attempts / review items
- `packages/audio`：Web Speech API 发音适配器（无后端、零成本）
- `apps/web`：三个 tab 的界面 + 挑战详情页交互，视觉对齐截图
- **不做**：账号登录、Supabase 云同步、真实 TTS 云服务、应用商店壳（留给后续阶段）

### 视觉基线（从截图提取）

- 白底、大留白、无边框卡片；主色为 iOS 系统蓝（`#007AFF` 一带）
- 标题 `Atomic Learning` 粗体居中，logo 在标题上方
- 词条胶囊：浅灰背景（约 `#F2F2F7`）、圆角全圆、深灰文字、右侧 ▶
- 播放器条：浅灰圆角矩形，内含 ▶ 与时间
- 正确原句：红色（判错态）；译文：灰色
- 底部 tab：三个等宽，选中项图标与文字加深加粗
